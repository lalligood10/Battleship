# Broadside – native iOS app (on hold)

> **Status:** the product is being built **web-first** — see the [main README](../README.md).
> This native SwiftUI app was written first and is kept here because it shares the same Firebase
> backend, security rules and game logic; it is a working starting point for an App Store version
> later. It has not been compiled in Xcode yet (it was written on Linux), so expect to fix small
> build errors when you first open it. Everything below is the original iOS guide.

Broadside is an iPhone game where you and a friend each hide a fleet of five ships on a
10×10 grid and take turns firing at each other's waters. Games are played over the internet,
turn by turn — you don't both need to be online at once, and you get a notification when it's
your move. Every finished game updates your rating, and there are Global, Weekly and Friends
leaderboards.

This README is written for the product owner (no coding experience needed). It explains what
you're looking at, what you need to buy/sign up for, and every step you have to do by hand.
The short version of those hand-steps is in **[MANUAL_STEPS.md](../MANUAL_STEPS.md)** (web) — the iOS-only steps are in §2–§6 below — use it as
your checklist.

> Naming note: the GitHub repo is called "Battleship", but the app is deliberately named
> **Broadside** and uses its own artwork so it doesn't infringe Hasbro's trademark.

## 1. What's in this repo

```
ios/          The iPhone app (Swift + SwiftUI, iOS 16 and newer) – this folder
web/          The web app (React) – the version currently being built and tested
functions/    The game server (Firebase Cloud Functions, TypeScript) – validates every move
firestore.rules      Database security rules (this is what keeps ships hidden from cheaters)
firestore.indexes.json  Database indexes the leaderboards/history need
firebase.json / .firebaserc   Firebase project configuration
```

### How the anti-cheat works (plain English)

- Your ship positions are saved in a private record that **only you** can read. The database
  rules literally refuse to hand that record to anyone else — including your opponent's phone.
- When you fire, your phone doesn't check the shot itself. It asks the server "I'm firing at
  B7", and the server looks at the opponent's hidden fleet and answers only
  *hit*, *miss* or *sunk*.
- The server also checks that it's actually your turn, that the cell is on the board, and that
  you haven't fired there before. A modified app can't cheat its way around any of that.
- Ratings, stats and leaderboards are only ever written by the server, never by phones.

### Technology choices (for the curious)

| Piece | Choice | Why |
| --- | --- | --- |
| App | Swift + SwiftUI, iOS 16+ | Native, modern Apple UI; light/dark mode for free |
| Backend | Firebase (Auth, Firestore, Cloud Functions, Cloud Messaging) | Realtime sync, generous free tier, first-class Swift SDK. Supabase was considered but Firebase's realtime listeners and callable functions fit the "hidden board + server-validated moves" design more directly. |
| Xcode project | Generated by [XcodeGen](https://github.com/yonaskolb/XcodeGen) from `ios/project.yml` | The `.xcodeproj` file is famous for merge conflicts; generating it avoids that |
| Rating | Elo, start 1000, K=32 | Industry standard; all the maths is in one file (`functions/src/game/scoring.ts`) |

## 2. Prerequisites (things you need before anything works)

1. **A Mac** running macOS 14 (Sonoma) or newer. iPhone apps can only be built on a Mac.
2. **Xcode 15 or newer** — free from the Mac App Store. It's a big download (~10 GB); start it early.
3. **An Apple Developer account** — https://developer.apple.com/programs/ (US$99/year).
   You need this to run on a real iPhone for more than a week, to use Sign in with Apple,
   push notifications, and TestFlight.
4. **A Google account** for Firebase (free "Spark" plan is fine to start; Cloud Functions
   require the "Blaze" pay-as-you-go plan, which still has a large free quota — expect $0/month
   at friends-and-family scale, but a card must be on file).
5. **Homebrew** (a Mac package installer). Open Terminal (⌘-Space, type "Terminal") and paste:
   ```
   /bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"
   ```
6. **Node.js 22** and the **Firebase CLI** (used to deploy the server). In Terminal:
   ```
   brew install node@22
   npm install -g firebase-tools
   ```

## 3. Set up the Firebase project (one-time, ~20 minutes)

### 3a. Create the project

1. Go to https://console.firebase.google.com and click **Add project**.
2. Name it e.g. `broadside`. Google Analytics can be turned **off**. Click **Create**.
3. Note the **Project ID** shown in *Project settings* (gear icon) — it looks like
   `broadside-1a2b3`. You'll paste it in a few places below.

### 3b. Turn on the pieces we use

1. **Authentication** → *Get started* → **Sign-in method** tab:
   - Enable **Apple**. (Leave the OAuth fields blank for now — iOS apps don't need them.)
   - Enable **Email/Password**.
2. **Firestore Database** → *Create database* → choose **Production mode** → pick a region
   close to you (e.g. `us-central1`, which is also where the functions run) → *Enable*.
3. **Upgrade to the Blaze plan** (bottom-left "Upgrade") — required for Cloud Functions.
   Set a budget alert (e.g. $5) so you'd be emailed if anything unexpected happened.

### 3c. Register the iPhone app and download its config file

1. In Project settings → *Your apps* → click the **iOS+** icon.
2. **Bundle ID**: `com.broadside.app` (must match exactly). Nickname: Broadside. Click *Register app*.
3. Click **Download GoogleService-Info.plist**.
4. Move that file into this repo at:
   ```
   ios/Broadside/Config/GoogleService-Info.plist
   ```
   (There's an `.example.plist` next to it showing what it looks like.) This file is
   **git-ignored on purpose** — it contains project keys and must never be committed. Without it
   the app launches to a "Firebase isn't configured yet" screen instead of crashing.
5. Skip the remaining "Add SDK" steps in the Firebase wizard — the code already has them.

### 3d. Tell the code your project ID

Open these files in any text editor and replace the placeholder:

| File | Replace | With |
| --- | --- | --- |
| `.firebaserc` | `broadside-dev` | your Project ID |
| `ios/project.yml` | `YOUR-FIREBASE-PROJECT-ID` (one place) | your Project ID |
| `ios/Broadside/Features/Game/GameScreen.swift` | `YOUR-FIREBASE-PROJECT-ID` (in `AppConfig.hostingDomain`) | your Project ID |
| `web/public/.well-known/apple-app-site-association` | `TEAMID` | your Apple **Team ID** (see §5, step 2) |

### 3e. Deploy the server

In Terminal, from the repo folder:

```
firebase login                      # opens a browser; sign in with the Google account from 3a
cd functions && npm install && cd ..
firebase deploy
```

This uploads the security rules, indexes, Cloud Functions, and the web app (build it first with `npm --prefix web run build`). It
takes 3–5 minutes the first time. Re-run `firebase deploy` whenever the server code changes.

> Sign in with Apple also needs the server side configured once: in Firebase Console →
> Authentication → Sign-in method → Apple, nothing extra is needed for native iOS sign-in.
> If you later add a website or Android, come back and fill in the Services ID fields.

## 4. Build and run the app in the iPhone Simulator

1. Install XcodeGen and generate the Xcode project (first time and after any file is added):
   ```
   cd ios
   ./generate.sh
   ```
   This creates `ios/Broadside.xcodeproj` (git-ignored) and warns you if the
   `GoogleService-Info.plist` is missing.
2. Open it: `open Broadside.xcodeproj` (or double-click it in Finder).
3. First open only: Xcode will "Resolve Package Dependencies" (downloading Firebase). Wait for
   the progress bar in the top bar to finish — a few minutes.
4. At the top of the Xcode window, choose a simulator such as **iPhone 15**, then press the
   **▶ Run** button (or ⌘R).
5. The Simulator launches with the app. **Email/password sign-in works in the Simulator.**
   Sign in with Apple and push notifications do *not* work in the Simulator (Apple
   limitation) — use a real iPhone for those.

To run the unit tests: **Product → Test** (⌘U). These cover board geometry, ship placement
rules, drag/rotate behaviour and the weekly-leaderboard week calculation. The server's own
tests (hit/miss/sunk, win detection, Elo, security rules) are in `functions/` — see §8.

## 5. Run on your own iPhone

1. In Xcode, click the blue **Broadside** project icon at the top of the left sidebar → the
   **Broadside** target → **Signing & Capabilities** tab.
2. Tick **Automatically manage signing** and choose your **Team** (sign in with your Apple ID
   via *Add an Account…* if it's not listed). Your **Team ID** (10 characters) is shown here —
   copy it into `web/public/.well-known/apple-app-site-association` replacing `TEAMID`, then
   `firebase deploy --only hosting` again.
   - To make the team choice permanent, put it in `ios/project.yml` under
     `settings.base.DEVELOPMENT_TEAM` and re-run `./generate.sh`.
3. Plug your iPhone into the Mac with a cable. On the phone tap **Trust** if asked.
4. On the iPhone: Settings → Privacy & Security → **Developer Mode** → On (restart when asked).
5. In Xcode's device menu (top bar) pick your iPhone, then press ▶ Run.
6. First run only: the phone will refuse to open the app until you trust the developer:
   Settings → General → VPN & Device Management → your Apple ID → **Trust**.

### 5a. Enable push notifications (APNs) — one-time, ~10 minutes

Turn notifications work only once Firebase can talk to Apple's push service:

1. Go to https://developer.apple.com/account/resources/authkeys/list → **+**.
2. Name it "Broadside Push", tick **Apple Push Notifications service (APNs)**, *Continue*, *Register*.
3. **Download** the `.p8` file (you can only download it once — keep it safe) and note the **Key ID**.
4. Firebase Console → Project settings → **Cloud Messaging** tab → *Apple app configuration* →
   **APNs Authentication Key** → *Upload*: pick the `.p8`, enter the Key ID and your Team ID.
5. Also at https://developer.apple.com/account/resources/identifiers/list make sure the App ID
   `com.broadside.app` exists with **Push Notifications**, **Sign in with Apple** and
   **Associated Domains** ticked (Xcode's automatic signing usually creates this for you).

Never commit the `.p8` file (it's git-ignored).

## 6. Share test builds with friends via TestFlight

1. Go to https://appstoreconnect.apple.com → **My Apps** → **+** → *New App*.
   Platform iOS, Name "Broadside", Bundle ID `com.broadside.app`, SKU `broadside`.
2. In Xcode: device menu → **Any iOS Device (arm64)**, then **Product → Archive**.
3. When the Organizer window appears, click **Distribute App** → **TestFlight & App Store** →
   keep the defaults → *Upload*. Wait 5–15 minutes for Apple to process it.
4. In App Store Connect → your app → **TestFlight** tab. The first time, answer the
   *Export Compliance* question: the app uses only standard HTTPS encryption → choose
   "None of the algorithms mentioned above" (the code also sets `ITSAppUsesNonExemptEncryption`
   to false so this usually isn't even asked).
5. **Internal Testing** → **+** create a group → add up to 100 people by their Apple ID email.
   They receive an email; they install the free **TestFlight** app and tap *Install*.
   Internal testers need no Apple review. (External testing via public link needs a short
   Apple review.)
6. For each new build: bump `CURRENT_PROJECT_VERSION` in `ios/project.yml` (1 → 2 → 3…),
   re-run `./generate.sh`, Archive, Upload.

## 7. How to play (what your testers will see)

1. Open the app → **Sign in with Apple** (or *Continue with Email*).
2. Pick a unique username ("call sign") — checked live against the server, with a profanity filter.
3. **New Game with a Friend** → you get a 6-letter code and a *Share invite link* button.
   Your friend enters the code under **Join with Code** or taps the link.
4. Both players **place ships** (drag to move, tap a selected ship or press *Rotate* to turn,
   *Shuffle* for a random legal layout) and press *Confirm fleet*.
5. Take turns tapping the enemy grid. Hits, misses and sunk ships are announced with haptics
   and sound. Push notifications tell you when it's your move.
6. First to sink all five ships wins. Ratings update immediately and the results screen reveals
   both fleets. Game history lives on the **Profile** tab.
7. **Resign** is at the bottom of the board. If an opponent goes silent for 3 days (configurable),
   a **Claim win** button appears for the waiting player.
8. **Quick Match** pairs you with whoever else is waiting in the queue.

Changeable game settings live in `functions/src/game/config.ts` (board size, whether ships
may touch, inactivity timeout) and `functions/src/game/scoring.ts` (Elo constants). Change,
then `firebase deploy --only functions`. Keep `ios/Broadside/Game/Board.swift` in sync for the
"ships may touch" flag and board size.

## 8. For developers: running the server tests locally

```
cd functions
npm install
npm test               # 47 pure unit tests: engine, Elo/stats, usernames, join codes, notifications
npm run test:emulator  # 31 integration tests against the Firestore emulator (needs Java 21)
npm run lint && npm run typecheck && npm run build
```

`npm run serve` starts the emulators so the app can be pointed at a local backend
(add `Functions.functions().useEmulator(withHost:port:)` in `GameService` if you want that).

## 9. Costs and limits to be aware of

- Firebase Blaze: free quota is ~2M function calls, 50k document reads and 20k writes **per day**.
  A game is roughly 100 reads/writes total, so hundreds of games a day are free.
- Apple Developer Program: $99/year.
- TestFlight builds expire after 90 days — upload a new build before then.

## 10. Troubleshooting

| Symptom | Fix |
| --- | --- |
| App shows "Firebase isn't configured yet" | The `GoogleService-Info.plist` is missing or in the wrong folder (§3c), or you didn't re-run `./generate.sh` after adding it. |
| "Missing or insufficient permissions" or a leaderboard tab never loads | Run `firebase deploy --only firestore` — rules or indexes not deployed. Indexes take a few minutes to build; the Firebase console → Firestore → Indexes tab shows progress. |
| "Sign in to continue" / functions fail with *unauthenticated* | Make sure Email/Password or Apple is enabled in Authentication (§3b). |
| No push notifications | Simulator never receives pushes. On device: complete §5a and accept the permission prompt. |
| Invite link opens the website but not the app | Associated domains need the Team ID in `apple-app-site-association` (§5 step 2) and the project ID in `project.yml`; reinstall the app after changing them. The web page also shows the code so the friend can type it. |
| Xcode: "No such module 'FirebaseAuth'" | Wait for package resolution to finish (File → Packages → Resolve Package Versions). |
